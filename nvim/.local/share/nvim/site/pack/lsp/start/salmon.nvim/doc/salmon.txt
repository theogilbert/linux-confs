1. INTRODUCTION                                                 *salmon-intro*

salmon swims upstream: put the cursor on a variable and |:Salmon| opens a
side pane showing the chain of points its value passed through, such as
assignments, aliases, parameters and the arguments callers pass, loop
variables, imports, in-place mutations, and optionally the expressions it
was derived from.

The pane is tied to the window you traced from (or the last window you used
`]s`/`[s` in). It closes when that window closes. If it would be the last
window left, it quits too, like `:q`.

Nodes are expanded lazily (only when opened), so deep or branching chains
stay cheap. While a node has a single expandable child, expansion continues
automatically (see |salmon-config| `auto_expand`).

                                                                *salmon-chain*
The chain reads top to bottom, in the order the value travels: where it
starts at the top, the traced symbol at the bottom. Above each step, a line
says in words how the value got there (see |salmon-labels|).
>
  ╷ defined
  ╪ base = 10                      main.py:10
  │ maybe defined (in a branch)
  ╪ base = 20                      main.py:12
  │ copied from another variable
  ┿ offset = base                  main.py:13
  │ passed as argument
  ┿ result = compute(offset, b=5)  main.py:14
  │ function parameter
  ┿ def compute(a, b):             main.py:4
  │ traced
  ╋ a                              main.py:5
<
Markers (box-drawing junctions, so the chain stays one unbroken line and
lines up in any font with box drawing; see `icons` in |salmon-config|):
  ╋   The traced symbol.
  ╪   End of the chain: nothing further upstream.
  ┼   More upstream, hidden: expand it.
  ┿   Expanded.
A step that may not happen (inside a branch or loop) says "maybe".

When a step has several inputs (derive mode, or the other inputs of an
update), the extra ones branch off to the right and merge back in with
`├─╯`.

Parallel inputs (call sites, several definitions) are ordered by closeness
to the traced symbol: same file first (nearest line first), then other
files, non-test before test files (a `test` or `tests` word in the path
below the directory shared with the traced file), nearest directory first.
The closest one continues the main line, which `[s` follows; the next ones
branch off nearest the step they feed into, in order (`]r` cycles through
them in that order).

A variable's history reads as a timeline on one line: its base DEF, then
each UPD and MUT, and each place it is read (RD), in source order. A pandas-style chain such as
`df = df.foo()` followed by `df = df.bar()` stays on one line.

2. REQUIREMENTS                                          *salmon-requirements*

- Neovim 0.11 or later.
- A tree-sitter parser for the buffer's language (required).
- An LSP server (optional, recommended). Used for `documentHighlight` (exact
  read/write occurrences), `definition` (imports, cross-file functions,
  globals) and `references` (call sites). Without one, salmon falls back to
  same-file, name-based tree-sitter heuristics, and follows imports by
  resolving relative module paths (Python, JS/TS, Lua `require`).

salmon has no per-language tables. It relies on conventions shared by
tree-sitter grammars: node type names (`if_statement`, `call_expression`)
and field names (`left`/`right`, `name`/`value`, `function`, `arguments`,
`parameters`).

3. COMMANDS                                                  *salmon-commands*

                                                                     *:Salmon*
:Salmon [trace]         Trace the identifier under the cursor and open the
                        pane.
:Salmon toggle          Close the pane if open, otherwise trace.
:Salmon close           Close the pane.
:Salmon derive          Toggle derive mode (see |salmon-derive|) and refresh.
:Salmon refresh         Rebuild the chain from the current root.
:Salmon next            Step forward, towards the traced symbol (like `]s`).
:Salmon prev            Step back, towards the definition (like `[s`).
:Salmon next_path       Next path leading to the selected step (like `]r`).
:Salmon prev_path       Previous path (like `[r`).

4. LABELS                                                      *salmon-labels*

  SYM   The symbol being traced (root).
  DEF   Defined here: end of the chain.
  CND   Conditionally assigned: inside a branch or loop that does not also
        enclose the use. Prefixes another label (e.g. CND DEF).
  ALS   Alias: assigned straight from another variable (`a = b`). Always
        followed.
  DRV   Derived from an expression (`c = f(a, b)`). Only in derive mode,
        otherwise shown as DEF.
  UPD   Update: a new value computed from the variable's own previous value
        (`df = df.dropna()`, `x += 1`).
  MUT   Mutated in place: `x[k] = v`, `x.a = v`, or `x.m(...)` used as a
        statement (a method call whose result is discarded).
  RD    Read on the way to the traced use, in the same scope: passed to a
        function (`f(x)`, says "passed to a function") or used in another
        expression (says "read"). End of chain.
  PRM   Function parameter. Expands to the call sites.
  ARG   Argument passed for that parameter at a call site.
  FOR   Loop variable. Expands to the iterated value.
  IMP   Import line (`from m import x`, `import { x }`,
        `x = require("m")`). Expands to the definition in the other module.
  SRC   A variable a derived expression depends on (derive mode).
  FN    A function a derived expression calls (derive mode). Expands to its
        RET nodes.
  RET   A return statement of that function.

                                                               *salmon-derive*
A bare identifier flowing into something (`a = b`, `f(b)`, `for x in b`,
`return b`) is a passage and is always followed. Any other expression is a
transformation and is only followed in derive mode. Under UPD and MUT nodes,
the variable itself and the methods called on it are hidden; only the other
inputs are shown.

5. PANE KEYMAPS                                               *salmon-keymaps*

                                                          *salmon-]s* *salmon-[s*
While the pane is open, these are mapped globally (any mapping they shadow,
such as the built-in spelling motions, is restored on close):

  [s            Step back along the path shown in the sign column
                (towards the definition) and show the step in the source
                window. A collapsed top is expanded first, so pressing `[s`
                repeatedly swims up the whole chain.
  ]s            Step forward along that path, towards the traced symbol.
  ]r            Show the next path leading to the selected step: when
                several inputs feed into it (call sites, derivation
                sources, timeline inputs), this switches the path drawn in
                the sign column, and `[s` follows it.
  [r            Show the previous path.

Jumps (`[s`, `]s`, <CR>, `p`) center the step in the source window when it
lands in another file or near the top or bottom edge.

In the pane:

  <CR>          Jump to the node (sets a jumplist entry).
  p             Preview: jump but keep focus in the pane.
  o <Tab> l     Expand / collapse.
  h             Collapse, or go to the step it flows into.
  R             Re-root the trace at this node.
  d             Toggle derive mode.
  r             Refresh.
  q             Close.
  g?            Show help and the label legend.
  K             Hover: what the node's labels mean, its location, the path
                from the traced symbol, whether it can be followed further (and
                why not), and the full source statement.

All of these can be changed via `keymaps` in |salmon-config|.

                                                                *salmon-folds*
The standard fold commands act on the chain. A "fold" is a step and
everything drawn above it (its upstream): the step itself when expanded,
otherwise the step it flows into:

  zo            Expand the node.
  zO            Expand recursively (up to `fold_depth` levels).
  zc            Collapse the fold the cursor is in.
  zC            Collapse it recursively.
  za / zA       Toggle / toggle recursively.
  zR / zn       Expand everything (up to `fold_depth` levels).
  zM / zN       Collapse everything below the root.
  zx / zX       Same as zM.
  zr            Expand all visible collapsed nodes at the shallowest level.
  zm            Collapse all expanded nodes at the deepest level.
  zi            Toggle between zR and zM.
  zj / zk       Move to the next / previous expandable node.
  [z / ]z       Move to the top / bottom (the step itself) of the current
                fold.
  zv            No-op (every node is always visible).

Fold creation and deletion (zf, zF, zd, zD, zE) do not apply.

6. CONFIGURATION                                               *salmon-config*

                                                              *salmon.setup()*
Calling `setup()` is optional. Defaults: >lua

  require("salmon").setup({
    derive = false,      -- follow derivations (DRV/SRC/FN/RET)
    auto_expand = 4,     -- auto-expand single-child chains this many levels
    fold_depth = 6,      -- depth limit for zO, zA, zR, zn
    width = 60,
    position = "left",  -- or "right"
    max_text = 60,       -- truncate source snippets
    -- step markers in the chain
    icons = { traced = "╋", expanded = "┿", collapsed = "┼", done = "╪",
              loading = "╂" },
    keymaps = {
      jump = { "<CR>" }, preview = { "p" }, toggle = { "o", "<Tab>", "l" },
      collapse = { "h" }, reroot = { "R" }, derive = { "d" },
      refresh = { "r" }, close = { "q" }, help = { "g?" },
      hover = { "K" },
      next = { "]s" }, prev = { "[s" },  -- global while the pane is open
      next_path = { "]r" }, prev_path = { "[r" },  -- likewise
    },
  })
<
salmon defines no global keymaps (besides `]s`/`[s` and `]r`/`[r` while the pane is open).
See |salmon-api| for mapping it.

7. HIGHLIGHTS                                              *salmon-highlights*

One group per label, `SalmonDEF`, `SalmonCND`, ... `SalmonRET`, plus
`SalmonLocation` for the file:line suffix and `SalmonGraph` for the chain's
lines (links to `Comment`).

In source buffers, while the pane is open:
  `SalmonOrigin`    Line of the traced symbol (dim background, links to
                  `CursorLine`).
  `SalmonSymbol`    Every occurrence of the traced variable (links to
                  `Search`). When the selected step is in another file,
                  the occurrences of its variable there.
  `SalmonSymbolOrigin`  The occurrence you traced from (links to
                  `IncSearch`).
  `SalmonSource`    With a node selected in a derivation source's upstream
                  (derive mode), every occurrence of that source's
                  variable (links to `DiffText`).
  `SalmonSelected`  The node selected in the pane (links to `Visual`).
  `SalmonFlowStep`  Step numbers in the sign column (links to `Title`).
  `SalmonFlow`      Lines between steps (links to `Special`).
  `SalmonOffPath`   In the pane, steps off the path shown in the sign column
                  (links to `Comment`).

The sign column shows one path through the selected node, from the top of
the chain down to the traced symbol; `[s`/`]s` walk along it. It is kept
while the selection stays on it; selecting a step off it switches to the
main line through that step. Each step is numbered (`4+` when more steps share a line), with a line between consecutive steps in
the same file. Its last segment has a heavy half (`╽` or `╿`) pointing at
the next step. Where the path continues in another file, the line turns
off to the left below the step (`─╯`); where it arrives from another file,
it comes in from the left above the step (`─╮`).

All groups are linked to standard groups by default (`default = true`), so a
colorscheme or your config can override them.

8. LUA API AND <PLUG> MAPPINGS                                    *salmon-api*

Every function can be passed directly as a keymap callback: >lua

  local salmon = require("salmon")
  vim.keymap.set("n", "<leader>ls", salmon.trace)
  vim.keymap.set("n", "<leader>lS", function() salmon.trace({ derive = true }) end)
<
                                                           *salmon.trace()*
salmon.trace({opts})       Trace the identifier under the cursor and open the
                           pane. {opts} (optional table):
                             `derive`  boolean: set derive mode first
                                       (persists, like |salmon.set_derive()|).
                             `focus`   boolean: move focus to the pane
                                       (default true). With `false` you stay
                                       in the source and can use `]s`/`[s`.
                                                        *salmon.trace_at()*
salmon.trace_at({buf}, {row}, {col}, {opts})
                           Same, at a position (0-based row, byte column).
                                                          *salmon.toggle()*
salmon.toggle({opts})      Close the pane if open, else |salmon.trace()|.
                                                           *salmon.close()*
salmon.close()             Close the pane.
                                                         *salmon.is_open()*
salmon.is_open()           Whether the pane is open.
                                                         *salmon.refresh()*
salmon.refresh()           Rebuild the chain from the current root.
                                              *salmon.next()* *salmon.prev()*
salmon.next() / prev()     Step forward / back along the chain, like `]s` /
                           `[s`. No-op when the pane is closed.
                                    *salmon.next_path()* *salmon.prev_path()*
salmon.next_path() / prev_path()
                           Show the next / previous path leading to the
                           selected step, like `]r` / `[r`.
                                                          *salmon.derive()*
salmon.derive()            Current derive mode (boolean).
                                                      *salmon.set_derive()*
salmon.set_derive({bool})  Set derive mode; refreshes an open pane.
                                                   *salmon.toggle_derive()*
salmon.toggle_derive()     Toggle derive mode.

                                                                *salmon-plug*
<Plug> mappings, for Vimscript users or plugin managers that take keys: >lua

  vim.keymap.set("n", "<leader>ls", "<Plug>(salmon-trace)")
<
  <Plug>(salmon-trace)      |salmon.trace()|
  <Plug>(salmon-toggle)     |salmon.toggle()|
  <Plug>(salmon-close)      |salmon.close()|
  <Plug>(salmon-refresh)    |salmon.refresh()|
  <Plug>(salmon-derive)     |salmon.toggle_derive()|
  <Plug>(salmon-next)       |salmon.next()|
  <Plug>(salmon-prev)       |salmon.prev()|
  <Plug>(salmon-next-path)  |salmon.next_path()|
  <Plug>(salmon-prev-path)  |salmon.prev_path()|

9. LIMITATIONS                                            *salmon-limitations*

These are heuristics, not a data-flow analysis:

- Reaching definitions are positional: the last unconditional write before
  the use, plus any conditional writes after it. Writes later in an
  enclosing loop body are not considered.
- Mutation detection is syntactic. A method call used as a statement counts
  (so does `df.head()` alone on a line). Mutation through another reference,
  or by passing the object to a function, is not tracked.
- Dynamic dispatch is not followed.
- Argument matching handles positional and keyword arguments and skips an
  implicit `self`/`cls`. `*args`/`**kwargs` show as unmatched.

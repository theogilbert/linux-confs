1. INTRODUCTION                                          *sections-introduction*

sections.nvim is a Neovim plugin that displays code sections (functions, 
classes, headers, etc.) in a sidebar panel. It uses Tree-sitter queries to
parse and extract structural information from your code, providing a quick
overview and navigation interface for your files.

The plugin supports hierarchical section display with collapsible nodes,
filtering of private/public sections, and quick navigation to any section
in your code.

================================================================================
2. REQUIREMENTS                                          *sections-requirements*

- Neovim 0.11.3+ with Tree-sitter support.
  Previous versions have not been tested.
- Tree-sitter parsers for the languages you want to use.
- A Nerd Font to properly display icons.

================================================================================
3. INSTALLATION                                          *sections-installation*

Using lazy.nvim: >lua
    {
        "sections.nvim",
        config = function()
            require("sections").setup()
        end,
    }
<

Using packer.nvim: >lua
    use {
        "sections.nvim",
        config = function()
            require("sections").setup()
        end,
    }

4. CONFIGURATION                                        *sections-configuration*

sections.nvim can be configured by passing options to the setup function:

>lua
    require("sections").setup({
        indent = 2,                           -- Indentation per level
        width = 40,                           -- Default width of the pane
        icons = {                             -- Icons for different section types
            ["function"] = "󰊕",
            class = "",
            attribute = "󰠲",
            header = "",
        },
        keymaps = {                           -- Keymaps within the sections panel
            toggle_private = "p",             -- Toggle private sections visibility
            select_section = "<cr>",          -- Jump to section in code
            collapse_section = "zc",          -- Collapse section
            expand_section = "zo",            -- Expand section
            toggle_section_collapse = "za",   -- Collapse/expand section
            show_description = "K",           -- Show section description
            close = "q",                      -- Close the panel
        },
    })
<

Configuration Options:~

*sections-config-indent*
`indent` (number, default: 2)
    Number of spaces to indent nested sections.

*sections-config-width*
`width` (number, default: 40)
    Default width of the sections pane when first opened.


*sections-config-icons*
`icons` (table)
    Icons displayed next to different section types. Defaults:
    - function: "󰊕"
    - class: ""
    - attribute: "󰠲"
    - header: ""

*sections-config-keymaps*
`keymaps` (table)
    Key mappings for the sections panel:
    - `toggle_private`: Toggle visibility of private sections (default: "p")
    - `select_section`: Jump to section in source code (default: "<cr>")
    - `collapse_section`: Collapse a section (default: "zc")
    - `expand_section`: Expand a section (default: "zo")
    - `toggle_section_collapse`: Collapse/expand a section (default: "za")
    - `show_description`: Show the section's description (default: "K")
    - `close`: Close the panel (default: "q")
    Set a keymap to `false` to disable it.

================================================================================
5. USAGE                                                        *sections-usage*

Open/close the sections panel:~
>
    :lua require("sections").toggle()
<
The panel opens directly to the left of the current window.

Jump to a section by name (the panel does not need to be open):~
>
    :SectionsJump [name]
    :lua require("sections").jump([name])
<
With no name, it is asked for on the command line with <Tab> completion
over the current buffer's sections. See |sections.jump()|.

The sections panel will display all parsed sections from the current buffer.
Sections are automatically refreshed when:
- You save the file
- You switch to a different window/buffer
- You enter a new buffer

Panel Features:~
- Hierarchical display of code sections
- Collapsible sections (functions, classes, etc.)
- Private section filtering (toggle with 'p' by default)
- Quick navigation to any section

================================================================================
6. KEYMAPS                                                    *sections-keymaps*

Default keymaps within the sections panel:

*sections-keymap-select*
`<cr>` - Jump to section in source code and focus the code window

*sections-keymap-collapse*
`zc` - Collapse the current section (if it has children)

*sections-keymap-expand*
`zo` - Expand the current section

*sections-keymap-toggle*
`za` - Collapse or expand the current section

*sections-keymap-description*
`K` - Show the current section's description in a floating window, see
|sections-descriptions|

*sections-keymap-close*
`q` - Close the panel and return to the code window

*sections-keymap-private*
`p` - Toggle visibility of private sections (e.g. Python functions starting with '_')

Note: These keymaps are only active when the cursor is in the sections panel.

7. SUPPORTED LANGUAGES                                      *sections-languages*

Each supported language has a query in `queries/<language>/sections.scm`.
A section has one of four types, which sets its icon and how its name is
displayed in the panel:

    Type        Displayed as          Icon (default)~
    function    `name(param, ...)`    󰊕
    class       `Name(Base, ...)`     
    attribute   `name: type`          󰠲
    header      `name`                

Sections found inside another section are shown as its children. SQL,
Lucene, PromQL, MongoDB and Cypher sections are comments, which never
contain one another: they are nested by level instead, see
|sections-subsections|. Sections marked as private can be hidden with the
`p` key (|sections-keymap-private|).

The examples below show a source snippet, followed by what the panel
displays.

*sections-lua*
Lua:~
- `function M.name(...)` → public function
- `function M:name(...)` → private function
- `function name(...)` and `local function name(...)` → private function
- `name = function(...)` and `local name = function(...)` → private function
Parameters are shown after the name. >lua
    local M = {}
    local function helper(a) end
    function M.setup(opts) end
<   Panel: >
    󰊕 helper(a)        (private)
    󰊕 M.setup(opts)
<
*sections-python*
Python:~
- Functions and methods, with their parameters
- Classes, with their base classes
- Class attributes (assignments in a class body), with their type annotation
- Module-level attributes, with their type annotation
Names starting with `_` are private. >python
    VERSION: str = "1"
    class Foo(Base):
        size: int = 0
        def run(self, x): ...
        def _check(self): ...
<   Panel: >
    󰠲 VERSION: str
     Foo(Base)
      󰠲 size: int
      󰊕 run(self, x)
      󰊕 _check(self)   (private)
<
*sections-markdown*
Markdown:~
- ATX headers (`#` to `######`), nested by level >markdown
    # Intro
    ## Details
    # Usage
<   Panel: >
     Intro
       Details
     Usage
<
*sections-json*
JSON:~
- Object keys, nested by object >json
    { "server": { "port": 80 }, "debug": true }
<   Panel: >
     server
       port
     debug
<
*sections-yaml*
YAML:~
- Mapping keys, nested by mapping >yaml
    server:
      port: 80
    debug: true
<   Panel: >
     server
       port
     debug
<
*sections-xml*
XML:~
- Elements, including self-closing ones, nested by element >xml
    <config>
      <server port="80"/>
    </config>
<   Panel: >
     config
       server
<
*sections-sql* *sections-lucene*
SQL and Lucene (`.lucene`, grannos parser):~
- Banner comments: a `-- name` line between two lines of three or more
  dashes, on consecutive lines. Boxing the name (`-- name --`) is optional.
  A description can follow in comments below the banner. The line of
  dashes closing a banner never opens another one. Other comments are
  ignored. Example (SQL): >sql
    ------------------
    -- Customers
    ------------------
    -- Active customers only
    SELECT * FROM customers WHERE active;
<   Panel: >
     Customers
<
- SQL only: the block comment banner of |sections-mongo| works too.
- Headings: `-- # name`, `-- ## name`, see |sections-subsections|.

*sections-promql*
PromQL (`.promql`, grannos parser):~
- Same banner as SQL, written with `#`: a `# name` line between two lines
  of three or more `#`. Boxing the name (`# name #`) is optional. Other
  comments are ignored. >
    ##################
    # Errors
    ##################
    # 5xx rate per job
    sum by (job) (rate(http_requests_total{code=~"5.."}[5m]))
<   Panel: >
     Errors
<
- Headings: `# # name`, `# ## name`, see |sections-subsections|.
*sections-mongo* *sections-cypher*
MongoDB (`.mongo`) and Cypher (`.cypher`, `.cyp`), grannos parsers:~
- Banner block comments: a `/*` followed by two or more stars, then
  ` * ` lines, closed by a line of stars ending in `*/`. Only the first
  inner line is used as the section name (the trailing `*` is optional),
  so further lines can hold a description. Other comments are ignored.
  Example (Mongo): >
    /******************
     * Orders         *
     * Open orders only *
     ******************/
    {"find": "orders", "filter": {"status": "open"}}
<   Panel: >
     Orders
<
- The SQL banner, written with `//`: a `// name` line between two lines of
  three or more `/`. Boxing the name (`// name //`) is optional. >
    //////////////////
    // Orders
    //////////////////
<
- Headings: `// # name`, `// ## name`, see |sections-subsections|.

*sections-subsections*
Subsections (SQL, Lucene, PromQL, MongoDB, Cypher):~
A banner is a level 1 section. A line comment alone on its line and
starting with `#` is a heading, whose level is the number of `#`, as for
Markdown headers: `-- # name` is a level 1 section like a banner,
`-- ## name` a level 2 one. A section is nested under the closest section
above it with a lower level; one with no such section is shown at the top
level. The comment marker before the `#` is the language's own: `--` for
SQL and Lucene, `#` for PromQL (`# # name`), `//` for MongoDB and Cypher.
The `#` must be followed by a space, so comments such as `-- #1 fix` are
ignored, and a comment trailing code, as in `SELECT 1; -- # note`, is
never a heading.
Example (SQL): >sql
    ------------------
    -- Customers
    ------------------
    -- ## Active
    SELECT * FROM customers WHERE active;
    -- ### By region
    SELECT region, count(*) FROM customers WHERE active GROUP BY region;
    -- ## Churned
    SELECT * FROM customers WHERE churned_at IS NOT NULL;
<   Panel: >
     Customers
       Active
         By region
       Churned
<
*sections-descriptions*
Descriptions (SQL, Lucene, PromQL, MongoDB, Cypher):~
A section's description is shown with `K` in the panel
(|sections-keymap-description|). It is made of the comment lines right
below the banner or heading, each alone on its line, stripped of the
comment marker (and of a closing box, as in `-- text --`). It ends at a
blank line, code, a rule, or a line starting another section. In a block
comment banner, the lines after the name are part of the description too.
Example (SQL): >sql
    ------------------
    -- Customers
    ------------------
    -- Every customer, active or not.
    -- Joined with their latest order.
    SELECT * FROM customers;
    -- # Orders
    -- Open orders only.
    SELECT * FROM orders WHERE status = 'open';
<
To add support for additional languages, create Tree-sitter query files
in the `queries/<language>/sections.scm` directory. See |sections-queries|.

Of course, a Tree-sitter parser also needs to be available for this language.

8. API                                                            *sections-api*

*sections.setup({config})*
    Initialize the plugin with optional configuration.
    
    Parameters:~
        {config} (table|nil) Configuration table, see |sections-configuration|

*sections.toggle()*
    Toggle the sections panel open or closed for the current tab.

*sections.focus()*
    Move the cursor into the sections panel.

*sections.jump({name})*                                          *:SectionsJump*
    Move the cursor to a section of the current buffer, recording the jump
    in the |jumplist|. The panel does not need to be open.

    Parameters:~
        {name} (string|nil) The section name. Nested sections are qualified
        with their ancestors' names, e.g. "Class.method". Resolution tries,
        in order: exact qualified name, bare name (last component), then
        case-insensitive substring; the name must be unambiguous within the
        first tier that matches.
        When nil or empty, the name is asked for with |input()| and native
        <Tab> completion over the buffer's sections (see
        |sections.complete()|).

    `:SectionsJump [name]` is the command equivalent, with the same
    completion.

*sections.complete({arglead})*
    Command-line completer over the current buffer's sections, usable as a
    `customlist` function (|:command-completion-customlist|), e.g. >
        completion = "customlist,v:lua.require'sections'.complete"
<
    Parameters:~
        {arglead} (string) The text typed so far

    Returns:~
        (string[]) Qualified section names containing {arglead},
        case-insensitively, in buffer order.

9. TREE-SITTER QUERIES                                       *sections-queries*

sections.nvim uses Tree-sitter queries to identify code sections. Query files
are located in `queries/<language>/sections.scm`.

Query Format:~
Queries should capture nodes with the following captures:
- `@section` - The entire section node
- `@section.name` - The section name
- `@section.param` - Section parameters (optional)
  Currently, parameters are only compatible with section types `function` and `class`.
- `@section.type_annotation` - Type annotations, displayed after `:` (optional)
- `@section.level` - Sets the section level to the length of its text, so
  it is usually rewritten with `#gsub!` first, e.g. to `##` (optional)
- `@section.description` - The section description, shown with `K`; usually
  rewritten with `#gsub!` (optional)

Metadata:~
- `(#set! type "function"|"class"|"attribute"|"header")` - Section type
- `(#set! private "true")` - Mark section as private
- `(#set! level "1")` - Section level. A section with a level is nested
  under the closest preceding section with a lower level, instead of the
  section whose node contains it. Used for sections that never contain one
  another, such as comments (see |sections-subsections|)
- `(#set! description_prefix "<pattern>")` - The comment lines right below
  the section's last captured node are its description, each stripped of
  the Lua <pattern>, e.g. `"^%-%-%s?"`. See |sections-descriptions|

Predicates:~
- `(#sections-banner? @rule @name @close)` - `@rule` opens a banner of
  line comments: `@name` is on the next line, `@close` on the line after,
  and `@rule` is not the rule closing a previous banner. A rule is a
  comment made of one repeated punctuation character, such as `------`
- `(#sections-own-line? @node)` - `@node` is alone on its line, i.e. it is
  not a comment trailing some code

Example query for functions:~
>query
    (function_definition
      name: (identifier) @section.name
      parameters: (parameters (identifier) @section.param)*
    ) @section
    (#set! type "function")
<
